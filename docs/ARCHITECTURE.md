# Architecture

How Meridian Observatory is built, what is generated from what, and how to check it. Written for M-002
(2026-10-28). `CLAUDE.md` holds the design history and measured facts; this file covers only the build.

Facts here are marked **[V]** (verified by a command run on 2026-10-28, named in place) or **[A]** (an assumption, or
read from code but not exercised).

## Technology

- A static site: plain HTML, CSS and ES modules served as files. GitHub Pages serves `main` as it is: no build runs
  on the server, so every generated file is committed. **[V]** (decision 0001)
- In the browser: three.js 0.186 (bundled), GSAP 3.15 and Lenis 1.3.27 (vendored in `assets/vendor/`, not bundled),
  Web Audio for sound, fonts in `assets/fonts/`. Nothing loads from a CDN (the site must work on networks where CDNs are unavailable).
- At build time: Node 22 (ES modules), esbuild 0.28.2 for bundling, Python 3 for page generation and stamping, and
  the npm packages pinned in `package-lock.json` (32 packages, all dev dependencies). **[V]** `node -v` v22.23.1,
  `npm ci` "added 32 packages"

               ─▶ rewrites every *.html: import map, ?v= on src/href, #preload list, speculation rules, ENTER script

Bundle inputs **[V]** from esbuild's metafile in `verify-build`: globe.js 2 own sources + 2 package files, world.js
5 + 139, world-paint.js 2 + 133. The data builders' inputs are read from their code **[A]**: they were not run.

Who loads what at run time **[V]** (grep): `home.js` imports `globe.js`; `chapter.js` imports `world.js`, and
`world.js` starts `world-paint.js` as a module worker by a URL relative to itself.

## Checks: `npm run check`

`tools/check.mjs` runs each stage in its own process from the repository root, does not stop at the first failure,
prints `PASS`/`FAIL` per stage, names the failed stages at the end and exits 1 if any failed. **[V]**

1. `check-econ` (Economics chapter fields, sources, indicators, syllabus coverage, no em dashes; also runs check-lab)
2. `check-lab` (policy-lab model directions)
3. `check-geo` (Tectonic hazards chapter)
4. `check-texels <data>` once per page that runs `chapter.js`, found by scanning `history/`, `economics/`,
   `geography/` (currently KQ6, Macro policy, Tectonics and the two engine test pages)
5. `verify-build` (below)
6. working tree unchanged: `git status --porcelain` and the content of every changed or untracked file are hashed
   before and after; any difference fails the run

`tools/verify-build.mjs` never writes inside the repository. It:

- rebuilds every `esbuild` command it finds in `package.json`'s scripts **in memory** with the same options and
  compares bytes; on a difference it prints the first differing byte with context and the bundle's own source files.
  It refuses an esbuild option it does not understand, and fails if the installed esbuild is not the pinned version;
- runs `tools/build-dots.mjs` with the `dots` script's argument in a temporary folder (`$TMPDIR/meridian-verify-*`,
  removed afterwards) and compares `src/land-dots.json`;
- copies the pages and the files `stamp.py` reads into a temporary folder, runs `pages.py` there and compares every
  page. A page whose only difference is its stamp is reported once per set of assets whose hash moved ("changed since:
  assets/js/core.js"); any other difference prints the changed lines and blames `tools/pages.py`;
- checks that every file named by a page's import map, `#preload` list, `<script src>` or stylesheet exists;
- for data it does not rebuild: every JSON under `assets/data` parses, every terrain tile in `index.json` exists and
  every tile on disk is listed, every DEM height image has its JSON;
- warns about untracked files `stamp.py` would hash (the pages would then name files the site lacks);
- hashes the files it compares before and after, and fails if any changed.

Verified on 2026-10-28: three consecutive runs gave identical output (timings removed), exit 0, about 2.5 s. Nine
deliberate corruptions in an isolated copy each failed for the expected reason (see the M-002 report).

## World engine

- `src/world/view.js`: camera placement and the screen footprint of a scene; shared by the engine and
  `tools/check-texels.mjs` (which imports it directly, unbundled).
- `src/world/paint.js`: painting of borders, fills, flags; shared by the engine (main thread fallback) and the worker.
- `src/world/engine.js`: the WebGL world (`createWorld`), terrain composition, overlays; `layers.js` Geography layers;
  `post.js` the optional post-processing (look 2).
- `src/world/paint-worker.js`: the OffscreenCanvas painter.
- `assets/js/chapter.js` (not bundled) renders a chapter from `<body data-chapter>` (KQ6 by default), loads
  `world.js` and the map data.

## Page generation and version stamping

- `pages.py` holds the shell (nav, footer, scripts) and the five generated pages' content inline. Chapter pages share
  none of it; they are edited by hand.
- `stamp.py` gives each page an import map (keys `./` or `../` + module path, values with `?v=` + the first 10 hex of
  the file's SHA-1), adds `?v=` to entry scripts and stylesheets, writes the `#preload` lists ("now": what hubs run on;
  "later": the rest and the map data; plus the size of `globe.js`), speculation rules and the inline view-transition
  hold (`ENTER`). It is idempotent: it strips its own blocks before writing them. **[V]** (`pages.py` in a copy
  reproduced all 11 pages byte for byte)
- Consequence: changing any `assets/js`, `assets/css` or `assets/vendor` file changes every page. `verify-build`
  reports that as one "old stamp" failure.

## Dependencies and caches

- `node_modules` is the repository's own (since M-002, 2026-10-28), installed by `npm ci` from `package-lock.json`.
  Before, it was a symlink to `../meridian/node_modules`. **[V]** The fresh install is file for file identical to the
  sibling's tree (`diff -rq --no-dereference`, no output), the lockfile's hash did not change, and `npm run check`
  passes on it.
  - How it was switched: `unlink node_modules` (removes only the link; `unlink` cannot recurse into the target), then
    `npm ci --prefer-offline --no-audit --no-fund` (2 s, from the local npm cache). `npm ci` writes only inside this
    repository's `node_modules` and never writes the lockfile.
  - Rollback: `rm -rf node_modules && ln -s ../meridian/node_modules node_modules`. Run it from this folder and write
    `node_modules` without a trailing slash: `rm -rf node_modules/` on a symlink would delete the sibling's packages.
  - A fresh clone needs `npm ci` before `npm run check` (the verifier says so if esbuild is missing).
- `tools/.cache` is still a symlink to `../../meridian/tools/.cache` (1.6 GB of downloaded inputs for the data
  builders). It is not a dependency: `npm run check` passes in a copy without it **[V]**. Only `build-maps`,
  `build-econ`, `build-geo` and `build-terrain` read or fill it, and they write into the sibling's folder through the
  link when run. Making it local means copying 1.6 GB; left for a later decision.

## Known reproducibility limits

- **`tools/.cache` is still the sibling's.** The symlink to `../../meridian/tools/.cache` remains (see Dependencies):
  the data builders read and fill the sibling's folder through it. `npm run check` does not use it.
- **Data is not reproduced.** `assets/data/**` comes from downloads (IMF, BIS, OWID, USGS, Copernicus, Natural Earth,
  CShapes, Berlin WFS), some of them live. M-002 checks only its integrity (parses, tiles indexed), not that it is what
  its builder would produce. Reproducing `borders.json` offline from `tools/.cache` may be possible **[A]**; not tried.
- **Hand-made binaries** (`relief-*.jpg` via `sips`, `og.jpg`, fonts, vendored libraries) have no recorded build.
- **Tool versions**: esbuild is pinned and checked. Node is declared as 22 (`.nvmrc`, `engines.node` `>=22 <23`; npm
  only warns on a mismatch) and CI uses Python 3.12; both CI guards fail on another major/minor version. Locally the
  pages reproduced identically with Python 3.12.14 and 3.14.7 **[V]**; other versions are untested. Pinning major
  versions does not make every environment reproduce the build: patch versions, the OS and npm's own version still vary.
- **The paint worker is not versioned**: `world.js` starts `world-paint.js` by a URL without `?v=` (import maps do not
  apply to worker URLs **[A]**), so a browser may pair a new `world.js` with a cached old worker for up to the Pages
  cache time (10 min). Not changed here (it would change loading behaviour).
- **CI** (M-002C): `.github/workflows/check.yml`, job `meridian-check`, runs `npm ci` and `npm run check` on pushes to
  `dev` and pull requests to `main`, read-only, with no deployment. It is a required check on `main` (GitHub Actions, App ID 15368, strict; see decision 0001).
- `check.mjs` relies on `git` for the unchanged-tree stage; outside a git checkout that stage fails.
